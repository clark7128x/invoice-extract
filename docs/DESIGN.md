# invoice-extract: проєктні нотатки

## Задача й обмеження

Пайплайн читає неструктурований текст рахунку й повертає JSON за схемою pydantic.
Поля: постачальник, номер, дата, валюта, загальна сума, ПДВ, список позицій.
Позиція містить назву, кількість і ціну.
ПДВ може бути відсутнім у тексті, тоді поле дорівнює `null`.

**Дані синтетичні.** `generate_data.py` створює 150 рахунків із фіксованим seed.
Спершу генерується правильний JSON, потім з нього рендериться текст у п'яти шаблонах.
Шаблони різняться форматами дат і сум, розміткою рядків і назвами полів.
У текст додаються шумові рядки й опечатки.
Розмітка точна за побудовою, бо текст походить із gold-JSON, а не навпаки.
Опечатки торкаються лише літерних слів: числа, дати й номери не спотворюються.
Назви місяців і позначення валют захищені від спотворення, інакше розбір ламався б штучно.
Частина рахунків не містить ПДВ у тексті; частка задається в `config.yaml`.

Обмеження:
- Python 3.11, без фреймворків оркестрації.
- Ключі й назви моделей беруться зі змінних середовища, параметри — з `config.yaml`.
- Модель отримує схему в промпті й вимогу повернути лише JSON.
- Після помилки валідації виконується щонайбільше два повтори.
- Числа в цьому README з'являються лише після запуску `eval.py`.

Синтетика не доводить якості на реальних сканах і PDF. Вона дає точну розмітку для порівняння двох моделей.

## Архітектура

Потік даних: gold-JSON → рендер тексту → JSONL → промпт зі схемою → LLM → розбір JSON → pydantic → повтор з текстом помилки → метрики → `results/`.

Компоненти:
- `invoices/generator.py` формує правильний JSON: позиції, суму без ПДВ, ПДВ, підсумок.
- `invoices/render.py` має п'ять шаблонів, форматує дати й суми, додає шум і опечатки.
- `invoices/schema.py` описує `Invoice` і `LineItem` та віддає JSON Schema для промпту.
- `invoices/normalize.py` перетворює дати, суми й валюти до канонічного вигляду.
- `invoices/pipeline.py` будує повідомлення, розбирає відповідь і керує повторами.
- `invoices/llm.py` викликає OpenAI-сумісний `/chat/completions` і логує кожен виклик.
- `invoices/calllog.py` пише JSONL з токенами й затримкою та рахує вартість.
- `invoices/metrics.py` рахує F1 по полях, вигадані значення, затримку й вартість.
- `invoices/report.py` рендерить markdown-таблиці.
- `eval.py` проганяє обидві моделі й пише `results/*.json`, `results/details_*.jsonl`, `results/metrics.md`.

Нормалізація виконується у валідаторах pydantic з `mode="before"`.
Модель може віддати «10 травня 2024 року» і «1 200,00 грн», схема отримає `2024-05-10` і `1200.0`.
Нерозпізнане значення піднімає `ValueError`, який стає помилкою валідації й іде в повтор.

Правила розбору чисел:
- розділювач, що стоїть правіше, вважається десятковим, якщо є і кома, і крапка;
- одиночна кома вважається десятковою;
- кілька ком або кілька крапок вважаються розділювачами тисяч;
- пробіли, символи валют і назви валют видаляються.

Правила розбору дат: `YYYY-MM-DD`, `DD.MM.YYYY`, `DD/MM/YYYY`, `DD-MM-YYYY`, «10 травня 2024 року», «10 тра 2024».
Числова дата з чотирицифровим роком праворуч читається як день-місяць-рік.

## Рішення й відкинуті альтернативи

- Схема в промпті, а не native structured output: працює з будь-яким OpenAI-сумісним сервером. `json_mode` в конфігу вмикає `response_format` для провайдерів, які його підтримують.
- JSON Schema генерується з pydantic-моделі, тому промпт і валідатор не роз'їжджаються.
- Повтор передає моделі список помилок з шляхами полів, а не загальне «спробуй ще».
- Нормалізація живе у схемі, а не в окремому кроці після валідації: помилка формату одразу стає сигналом для повтору.
- `extra="forbid"` ловить зайві ключі замість мовчазного їх відкидання.
- Мікро-F1 по полях з підрахунком TP, FP, FN, TN на документ.
- Назви порівнюються з допуском в одну редакторську відстань, бо рендер вставляє односимвольні опечатки. Номер і дата порівнюються строго.
- Позиції зіставляються жадібно за збігом усіх трьох полів; порядок позицій не впливає на бал.
- Невдала валідація після всіх спроб рахується як пропуск усіх gold-полів, а не виключається з вибірки.
- Вартість рахується з логів викликів, включно з повторами.
- Відкинуто регулярки без моделі: п'ять шаблонів покриються, реальний текст — ні, і порівняння моделей втратить сенс.
- Відкинуто окремий виклик на кожне поле: множиться вартість і затримка без виміряної вигоди.
- Відкинуто LangChain і подібні: цикл повторів займає один файл.

## Оцінка якості

`eval.py` читає `data/invoices.jsonl` і проганяє кожну модель з `eval.models`.

Метрики для кожної моделі:
- F1 по кожному полю: `supplier`, `number`, `date`, `currency`, `total`, `vat`, `items`, `items.name`, `items.quantity`, `items.unit_price`.
- Частка відповідей, що пройшли валідацію з першої спроби.
- Частка вигаданих значень у полях, яких у документі немає.
- Вартість за 1000 документів.
- Медіанна й p95 затримка.

Правила підрахунку для скалярного поля на одному документі:
- gold є, прогноз збігається — TP;
- gold є, прогноз інший — FP і FN;
- gold є, прогнозу немає — FN;
- gold немає, прогноз є — FP і зараховується як вигадане значення;
- gold немає, прогнозу немає — TN, у F1 не входить.

F1 = 2·TP / (2·TP + FP + FN). Він не визначається, коли поле не має жодного додатного випадку; тоді в таблиці стоїть «не виміряно». Коли випадки були, а збігів немає (зокрема після невдалої валідації), F1 дорівнює 0, а не «не виміряно».
Знаменник частки вигаданих значень — кількість пар (документ, поле), де gold дорівнює `null`.
Зараз генератор робить необов'язковим лише ПДВ, тому метрика охоплює це поле; розбиття по полях є у JSON.
Затримка міряється на документ і включає всі спроби.
Вартість за 1000 документів = виміряна вартість набору / кількість документів × 1000.

## Вартість і затримка

Кожен виклик дописує рядок у `results/calls.jsonl`: час, модель, вхідні токени, вихідні токени, затримка, статус, `doc_id`, номер спроби.
Токени беруться з `usage` відповіді; якщо провайдер їх не віддає, поле лишається `null`, а вартість не рахується.
Ціни задаються в `config.yaml` окремо для малої й великої моделі.
Ціни не задані, доки їх не вписано, тому вартість у таблицях — «не виміряно».
Мережеві повтори й повтори валідації пишуться в той самий лог, тому вартість включає обидва види.

| Модель | Викликів | Вхідні токени | Вихідні токени | p50, мс | p95, мс | Вартість |

| small | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно | не виміряно |

## Що зламалося

Прогону з реальною моделлю ще не було. Нижче — режими відмови, які видно з коду й тестів.

- Одиночна кома читається як десяткова. Запис «1,234» у значенні тисячі дає 1.234. Генератор такого формату не створює, реальний документ може.
- Одиночна крапка теж читається як десяткова. «1.234» у значенні тисячі дає 1.234.
- Числова дата без чотирицифрового року відхиляється замість вгадування.
- `extra="forbid"` відправляє модель на повтор через нешкідливий зайвий ключ. Це свідома ціна строгості.
- Опечатка в назві позиції може збігтися з іншою назвою при допуску в одну відстань. Жадібне зіставлення бере перший збіг, а не найкращий.
- Шумовий рядок з IBAN і кодом ЄДРПОУ стоїть поруч із номером рахунку й провокує підміну поля.
- «Без ПДВ» і `vat = 0` різні стани. Модель, що повертає 0 замість `null`, отримує FP і зараховується як вигадане значення.
- Метрика вигаданих значень покриває лише ПДВ, бо тільки це поле генератор вміє приховувати.
- Синтетичні шаблони не містять сканів, переносів таблиць між сторінками й змішаних мов у назвах.

## Що змінив би

- Додав перевірку `total ≈ сума позицій + ПДВ` як окремий діагностичний сигнал. Заплановано.
- Додав необов'язкові поля крім ПДВ, щоб метрика вигаданих значень мала більше одного поля. Заплановано.
- Замінив жадібне зіставлення позицій на оптимальне призначення. Заплановано.
- Додав шаблон із OCR-шумом у цифрах і окрему gold-розмітку для нього. Заплановано.
- Додав прогон на кількох реальних рахунках з ручною розміткою. Заплановано.
- Виніс ціни моделей у конфіг із посиланням на прайс провайдера. Заплановано.

## Як запустити

Без ключа й без мережі:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python generate_data.py
pytest -q
```

З моделлю:

```bash
cp .env.example .env
# впиши LLM_API_BASE, LLM_API_KEY, LLM_MODEL_SMALL, LLM_MODEL_LARGE
set -a; source .env; set +a

# рахунок із файлу або зі stdin
python extract.py invoice.txt --model small
cat invoice.txt | python extract.py

python eval.py
python eval.py --models small --limit 20
```

Вартість з'явиться після того, як впишеш `price_per_1m_input` і `price_per_1m_output` для обох моделей у `config.yaml`.
Файл `.env` не читається автоматично, змінні експортує команда `set -a; source .env; set +a`.
Результати: `results/metrics.md`, `results/eval_<час>.json`, `results/details_<час>.jsonl`.
`eval.py` виходить з кодом 2 і нічого не рахує, якщо набір порожній.
